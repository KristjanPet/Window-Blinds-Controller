# TMC2209 Driver

This module configures and verifies the TMC2209 stepper motor driver over UART and forwards DIAG/StallGuard events to the main blinds command queue.

Datasheet: [TMC2209 Datasheet Rev. 1.09](https://www.analog.com/media/en/technical-documentation/data-sheets/tmc2209_datasheet_rev1.09.pdf)

Stepper motor used for project: [Nema 17 17HS4401](https://www.alldatasheet.com/datasheet-pdf/pdf/1245671/NINGBO/17HS4401.html)

## Purpose

The driver is responsible for:

- ESP32-S3 UART communication with the TMC2209
- TMC2209 register read/write access
- initial motor-driver configuration
- communication verification after configuration
- DIAG interrupt handling
- forwarding stall events to `BlindsCommandQueue`

High-level blind movement decisions are handled by `BlindsController`. Step pulse generation and position tracking are handled by `MotorController`.

## Used pins

| ESP32-S3 pin | TMC2209 pin / signal | Used by | Description |
|---|---|---|---|
| `GPIO17` | `PDN_UART` / UART TX | `Tmc2209Driver` | ESP32 UART transmit line used for TMC2209 register access |
| `GPIO18` | `PDN_UART` / UART RX | `Tmc2209Driver` | ESP32 UART receive line used for TMC2209 replies |
| `GPIO9` | `DIAG` | `Tmc2209Driver` | StallGuard/diagnostic output; configured as interrupt input |
| `GPIO15` | `STEP` | `MotorController` | Step pulse input generated by ESP32 RMT |
| `GPIO7` | `DIR` | `MotorController` | Motor direction control |
| `GPIO8` | `ENN` | `MotorController` | Driver enable control |

UART configuration:

| Setting | Value |
|---|---|
| ESP-IDF UART port | `UART_NUM_2` |
| Baud rate | `115200` |
| TMC2209 node address | `0x00` |
| Sync byte | `0x05` |
| Write bit | `0x80` |
| Expected TMC2209 version | `0x21` |

## Used UART register addresses

| Address | Register | Access | Project setting / use |
|---|---|---|---|
| `0x00` | `GCONF` | Write | Set to `0x000000C0` through `AppConfig::motorGConfig`. Enables UART control and register-based microstep configuration. |
| `0x02` | `IFCNT` | Read | Read before and after configuration. Used to verify that the expected number of UART writes was accepted. |
| `0x06` | `IOIN` | Read | Used to verify the TMC2209 version field. Expected version is `0x21`. |
| `0x10` | `IHOLD_IRUN` | Write | Set to `0x00081F08`: `IHOLD = 8`, `IRUN = 31`, `IHOLDDELAY = 8`. |
| `0x13` | `TPWMTHRS` | Write | Set to `0`. Used as part of the StealthChop/StallGuard operating threshold setup. |
| `0x14` | `TCOOLTHRS` | Write | Set to `1000`. Used to define the velocity range where StallGuard/DIAG operation is active. |
| `0x40` | `SGTHRS` | Write | Set to `95`. StallGuard threshold used for stall detection. |
| `0x41` | `SG_RESULT` | Read | Read during testing/tuning to monitor StallGuard load measurement. Masked with `0x03FF`. |
| `0x6C` | `CHOPCONF` | Read/write | Current value is read first, then configured to `0x15000053` with 1/8 microstep setting. |

## StallGuard tuning

StallGuard was tuned experimentally on the actual blinds mechanism.

The tuning process:

1. Move the blinds at the normal operating speed.
2. Continuously monitor `SG_RESULT` during normal movement.
3. Measure `SG_RESULT` near higher-load regions and near mechanical end stops.
4. Compare normal-motion values against values measured during stall or near-stall conditions.
5. Choose an `SGTHRS` value that avoids false stall detection during normal movement but reliably triggers DIAG when the motor stalls.

The final project value is:

| Parameter | Value | Meaning |
|---|---:|---|
| `SGTHRS` | `95` | StallGuard threshold written to register `0x40` |
| Effective compare level | `190` | TMC2209 compares `SG_RESULT` against approximately `SGTHRS * 2` |
| `SG_RESULT` mask | `0x03FF` | Keeps the 10-bit StallGuard result value |

The threshold was chosen using measurement plots from monitored `SG_RESULT` values. Normal movement should stay above the selected threshold with margin, while real stalls should drop below it and generate a DIAG pulse.

## Event handling

The DIAG pin is configured as a rising-edge interrupt input. When the interrupt fires, the driver sends a `STALL_DETECTED` event into `BlindsCommandQueue`.

The driver does not decide how to recover from the stall. Recovery behavior is handled by `BlindsController`.

## Verification

`configureAndVerify()` performs the startup configuration and checks that communication is working:

1. Read `IFCNT`.
2. Write all required configuration registers.
3. Read `IFCNT` again and check that it increased by the expected number of writes.
4. Read `IOIN`.
5. Check that the reported TMC2209 version matches `0x21`.

If verification fails, the driver returns an ESP-IDF error and startup can enter a fault path instead of silently continuing with an unverified motor driver.
